Infosys Java Full Stack Developer — Interview Prep Guide

Compiled from real 2025–2026 Infosys interview reports (Glassdoor, Medium, InterviewEra, PrepInsta) plus standard core-Java/Spring fundamentals. Typical process: 1–2 technical rounds (Java + Spring + a coding problem) → sometimes a frontend round (JS/Angular/React) → HR round.

1. Actual Questions Reported by Recent Infosys Candidates

Backend round (2025 reports):

  • Write the structure of a REST API. What is Spring Boot Actuator? What does the Spring Initializer do?
  • What is an Entity (JPA)? How do you improve API performance?
  • What is single sign-on / token-based authentication vs authorization?
  • How do you do unit testing in your project? Which annotations (@SpringBootTest, @MockBean, @WebMvcTest, JUnit 5 + Mockito)?
  • Coding: Given a string, print the count of repeating characters using Java 8+ Streams (Collectors.groupingBy).
  • How does HashMap work internally? (hashing, buckets, collision chaining, load factor/resize)
  • What is an API Gateway?
  • Explain your project's architecture (microservices, CI/CD, tech stack).
  • How do microservices communicate — sync (REST) vs async (Kafka/SQS)? What is service discovery?
  • What is the Circuit Breaker pattern? (Resilience4j / Hystrix)

Frontend round (if full stack — Angular or React, varies by panel):

  • Pipes, component lifecycle, lazy loading, how to consume an API in the frontend (Angular)
  • Hoisting, closures, == vs ===, var/let/const, event loop & call stack, map/filter/reduce, shallow vs deep copy, JS memory management/GC (JavaScript)
  • Conditional rendering, list rendering, lifecycle methods, state management (useState/useReducer/Context/Redux), React Router, async/await (React)

HR/behavioral: Tell me about yourself, why Infosys, strengths/weaknesses, willingness to relocate, project ownership stories.

2. Core Java — Theory

  • OOP pillars: encapsulation, inheritance, polymorphism (compile-time vs runtime), abstraction
  • abstract class vs interface; default & static methods in interfaces (Java 8+)
  • == vs .equals(); contract between equals() and hashCode()
  • String pool, why String is immutable, String vs StringBuilder vs StringBuffer
  • final, finally, finalize() differences
  • Access modifiers; method overloading vs overriding; super/this
  • Static vs instance members; static initializer blocks; static nested class vs inner class
  • Constructors: default, parameterized, constructor chaining, copy constructor
  • Exception hierarchy: checked vs unchecked, try-with-resources, custom exceptions, throw vs throws
  • Wrapper classes, autoboxing/unboxing, integer caching (-128..127)
  • Java memory model: stack vs heap, method area, PermGen/Metaspace
  • Garbage collection: generational GC (Eden → Survivor → Old Gen), minor vs major/full GC, G1GC, when OutOfMemoryError happens
  • Object class methods: equals, hashCode, toString, clone, wait/notify
  • Serialization: Serializable, transient, serialVersionUID
  • Java 8+ features: lambdas, functional interfaces, Streams API, Optional, method references, default/static interface methods
  • Java 9–17+ highlights (if asked): modules, var, records, sealed classes, pattern matching, text blocks, switch expressions

3. Collections Framework

  • List vs Set vs Map vs Queue; ArrayList vs LinkedList (internal structure, when to use which)
  • HashMap internal working: hashing, bucket array, equals/hashCode, treeification (Java 8+ red-black tree on collision), resize/rehashing, load factor
  • HashMap vs Hashtable vs ConcurrentHashMap vs TreeMap vs LinkedHashMap
  • HashSet vs TreeSet vs LinkedHashSet
  • Comparable vs Comparator
  • Iterator vs ListIterator; fail-fast vs fail-safe iterators; ConcurrentModificationException
  • ArrayDeque, PriorityQueue
  • Time complexity of common operations across these collections

4. Multithreading & Concurrency

  • Process vs thread; creating threads (Thread class vs Runnable vs Callable)
  • Thread lifecycle: new, runnable, running, blocked/waiting, terminated
  • synchronized (method vs block), intrinsic locks, volatile keyword
  • wait(), notify(), notifyAll()
  • ExecutorService, thread pools, Future/CompletableFuture
  • java.util.concurrent: ConcurrentHashMap, CountDownLatch, Semaphore, ReentrantLock
  • Deadlock, race condition, how to avoid them
  • Producer-consumer problem (classic coding question)

5. Exception Handling

  • Exception hierarchy: Throwable → Error / Exception → checked/unchecked
  • Try-catch-finally flow, multi-catch, try-with-resources
  • Custom exception design, best practices for exception handling in REST APIs (@ControllerAdvice, @ExceptionHandler)

6. Spring / Spring Boot — Theory

  • Spring core: IoC container, Dependency Injection (constructor vs setter vs field), Bean lifecycle, @Component/@Service/@Repository/@Controller
  • Bean scopes: singleton, prototype, request, session
  • @Autowired, @Qualifier, @Primary
  • Spring Boot: auto-configuration, starters, @SpringBootApplication, embedded servers, application.properties/yml, profiles
  • Actuator — health checks, metrics, monitoring endpoints (this came up directly in a real Infosys interview)
  • Spring Initializr — bootstrapping a project
  • Building REST APIs: @RestController, @RequestMapping, @GetMapping/@PostMapping/@PutMapping/@DeleteMapping, @PathVariable, @RequestParam, @RequestBody, ResponseEntity
  • Validation (@Valid, @NotNull, etc.), global exception handling
  • Spring Data JPA: @Entity, @Id, @OneToMany/@ManyToOne/@ManyToMany, repositories (JpaRepository), custom queries (@Query), lazy vs eager loading, N+1 query problem
  • Transactions: @Transactional, propagation, isolation levels
  • Security: Spring Security basics, JWT-based authentication, OAuth2, filters
  • Caching: @Cacheable, Redis integration basics
  • Testing: JUnit 5, Mockito, @SpringBootTest, @WebMvcTest, @DataJpaTest, @MockBean

7. Microservices & System Design (asked heavily at Infosys)

  • Monolith vs microservices — trade-offs
  • Service discovery (Eureka), API Gateway (Spring Cloud Gateway/Zuul) — purpose: routing, load balancing, auth, rate limiting
  • Config server, centralized configuration
  • Inter-service communication: synchronous (REST, Feign client) vs asynchronous (Kafka, RabbitMQ, SQS)
  • Circuit Breaker pattern (Resilience4j/Hystrix), retry, fallback, bulkhead
  • Distributed tracing (Sleuth/Zipkin), centralized logging (ELK)
  • Idempotency, eventual consistency, saga pattern (basic awareness)
  • Docker & Kubernetes basics — containerization, pods, deployments (good to know at a high level)
  • CI/CD pipeline overview

8. Database / SQL

  • SQL joins (inner/left/right/full), GROUP BY/HAVING, subqueries vs joins
  • Indexing — how it speeds up reads, trade-off on writes
  • Normalization (1NF–3NF), ACID properties
  • Primary key vs foreign key vs unique key
  • Query optimization basics, EXPLAIN plan awareness
  • SQL vs NoSQL, when to use MongoDB/Redis vs RDBMS

9. Likely Coding Questions (practice these in Java)

Strings

  1. Count repeating characters in a string using Java 8 Streams (Collectors.groupingBy + Collectors.counting()) — asked directly at Infosys
  2. Check if a string is a palindrome
  3. Reverse a string / reverse words in a sentence
  4. Find first non-repeating character
  5. Check if two strings are anagrams
  6. Longest substring without repeating characters

Arrays

  1. Find duplicates in an array
  2. Find the missing number in a range
  3. Two Sum problem
  4. Rotate an array by k positions
  5. Find the largest/second-largest element
  6. Merge two sorted arrays

Collections/HashMap

  1. Word frequency counter using HashMap
  2. Group anagrams together
  3. Implement your own simple HashMap (explain bucket + collision logic) — asked as a theory follow-up to "how does HashMap work"

Linked List

  1. Reverse a linked list
  2. Detect a cycle (Floyd's algorithm)
  3. Find the middle node

OOP / Design

  1. Implement Singleton pattern (thread-safe, e.g. double-checked locking or enum-based)
  2. Design a simple LRU Cache using LinkedHashMap
  3. Producer-Consumer using wait/notify or BlockingQueue

SQL

  1. Second-highest salary query
  2. Find duplicate rows
  3. Department-wise max salary using GROUP BY

Java 8 Streams (Infosys leans on these)

  1. Sort a list of objects by a field using Comparator + Streams
  2. Convert a List<Object> to a Map using Collectors.toMap
  3. Filter and transform a list in one pipeline

10. Frontend (if the role is truly full stack)

Know at least one framework deeply (Angular or React — match whatever is in your resume/project):

  • Angular: components, modules, services, dependency injection, pipes, @Input/@Output, lifecycle hooks, RxJS observables, lazy loading, routing, HttpClient for API calls
  • React: hooks (useState, useEffect, useReducer, useContext), component lifecycle, conditional/list rendering, state management (Context/Redux), React Router, calling APIs with fetch/axios
  • JavaScript core: hoisting, closures, == vs ===, var/let/const, event loop, map/filter/reduce, promises/async-await, shallow vs deep copy

11. How to Prepare (1-week plan)

DaysFocus
1–2Core Java + Collections + Multithreading theory, revise with your own words
3Spring Boot + Spring Data JPA + REST API design
4Microservices concepts (Gateway, Circuit Breaker, Kafka basics) + SQL practice
5Coding practice — the list above, in Java, on paper/whiteboard style (no IDE autocomplete)
6Frontend framework revision + mock explain of your own project architecture end-to-end
7Mock interview / rehearse "tell me about yourself" + project deep-dive + revise weak spots
Tip specific to Infosys panels: they weight practical, production-level understanding over pure algorithmic speed — be ready to explain why you made a design choice in your own project (why this DB, why this pattern, how you'd scale it), not just recite definitions.

Good luck with the interview!
